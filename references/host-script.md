# 独立婚礼主持稿

主持稿根据本场新人和本场仪式写作，并独立于时间表、物品清单与执行表交付。

## 先确定事实与声音

- 优先使用用户指定的文风、口播习惯和本场流程。
- 历史主持稿只作为风格与篇幅参考，不能搬用其中的相识经历、姓名、亲属关系、地点、对话或承诺。
- 只有已确认的经历才能写成叙事。资料没有爱情故事时，使用不包含虚构经历的简洁表达；需要个性化细节的位置可以标“待确认”。
- 关系或称谓不清楚时保留待确认，不自行写成父亲、母亲、爷爷、朋友等身份。

## 篇幅与结构

有用户样本时，统计同类环节的口播正文长度，使用同一统计口径，并排除标题、舞台指令和重复版本。报告样本数量与大致长度范围，再结合本场环节和用户要求调整。整稿样本不能直接当作开场白的目标长度。

没有样本时，优先遵循用户指定的时长或字数；两者都没有时，以本场流程和自然口播为准，不强制固定字数。不把未经测试的字数换算成精确朗读时长。

依据已确认流程组织环节，例如开场、入场、誓言、戒指、致辞、祝福和礼成；只写本场需要的部分。正式口播与必要舞台提示分开，让主持人能直接朗读。没有确定的音乐、灯光、站位或递送人员，不在提示中将其写成既定安排。

## 可选的温暖叙事方向

用户没有指定文风时，可采用温暖、真实、克制的方向：从本场具体细节出发，用适合说出口的短句连接情绪，避免连续堆砌形容词。它只是参考，不覆盖用户的幽默、庄重、简洁等偏好。

可从资料中选择三至五处真实细节，用一个贴合新人的核心意象串联，由日常相处自然走向今天的承诺。资料不足时减少细节，不为了凑数编故事。短句之间留出自然停顿；情绪递进后回到下一项已确认的仪式动作，避免长篇抒情打断现场节奏。

不套用旧故事，不假装见证未提供的经历，不代新人表达未经确认的敏感承诺。主持人的语言服务于新人，不默认加入个人品牌、签名口号或宣传。

## 交付检查

逐项核对姓名、称谓、人物关系、故事出处和仪式顺序。检查衔接是否依赖尚未确认的环节；确有依赖时明确标注。提供可直接使用的稿件；文档生成能力不可用时，交付完整可复制正文并说明格式限制。
